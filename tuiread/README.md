# TuiRead (userscript)

**English** | [Tiếng Việt](README.vi.md)

A **Tampermonkey** / **Violentmonkey** userscript for reading raw Chinese web novels: it converts the chapter to Vietnamese in place, using the VietPhrase dictionary. Translation runs entirely in your browser; page content is not sent anywhere.

This is a userscript build of the [TuiRead](https://github.com/memories169/tuiread-firefox) extension (the Firefox port of [ppptran/tuiread](https://github.com/ppptran/tuiread)). The translation engine and `content.js` are embedded unchanged from that repo, and the dictionaries are downloaded from it.

> The script's interface is in Vietnamese. Menu and button names are given below in their original form, followed by their meaning.

## Install

1. Install Tampermonkey or Violentmonkey in your browser.
2. Open this link and your userscript manager will show its install page:
   **https://raw.githubusercontent.com/loooveee/script/main/tuiread/tuiread.user.js**

Installed this way, the script updates automatically.

## Usage

Open a chapter on `uukanshu.cc` or `piaotia.com` and the story text turns into Vietnamese.

- **The first time on each site**, the script downloads about 45MB of dictionaries from GitHub and stores them in that site's IndexedDB. A chip in the bottom-right corner shows progress. Later visits do not download again.
- **Click a translated phrase** to see the original Chinese and fix its meaning. **Lưu** (save) applies to the current novel, **Lưu vào VP** applies to every novel.
- **The options panel** opens from the round **TR** button in the bottom-left corner, or from **TuiRead: Tùy chọn** (options) in the Tampermonkey/Violentmonkey menu. It has:
  - the per-site on/off switch, display mode (Vietnamese only, or Vietnamese with the Chinese original below), light/dark theme;
  - meaning selection: first meaning only, dropping 的/了/着/著, number-date-unit rules, name detection;
  - your own dictionary (patches for every novel): edit in place, import/export `.txt`, load from a URL;
  - per-novel dictionaries, your own pattern rules, the story-area selector, and a test box.
- **Adding another novel site**: open that site and choose **TuiRead: bật trên site này** (enable on this site) in the menu. If the script picks the wrong block as the story, paste the right CSS selector under **Site & selector khu vực truyện**.

## Differences from the extension

| | Extension | Userscript |
|---|---|---|
| Dictionaries | Bundled | Downloaded once per site, stored in that site's IndexedDB |
| Engine | One copy shared by the whole browser | Runs in a Web Worker in each tab; frees its memory after 3 idle minutes |
| Changing chapter | Engine already loaded | The script translates the next chapter into the cache ahead of time, so it shows Vietnamese at once (can be turned off in the options) |
| Settings, patches | `chrome.storage` | The userscript manager's storage, shared across sites |
| Font | SF Pro Display | System font |

## Notes

- **The script declares `@match *://*/*`** so sites can be added at runtime, but it only does anything on `uukanshu.cc`, `piaotia.com` and sites you added. Elsewhere it only registers one menu command.
- **Each tab that is translating holds a copy of the dictionary in memory** (roughly 150–300MB) until it has been idle for 3 minutes.
- **Translating the next chapter ahead sends one extra request to the site per chapter**, and has no effect on sites that load chapter text with JavaScript.
- **On pages that block Web Workers** the engine runs on the page itself: the page stalls for a few seconds whenever the dictionary loads, and the next chapter is not translated ahead.

## Rebuilding from upstream

`tuiread.user.js` is generated by `build.mjs` from `src/userscript.template.js` and the extension's source. When upstream changes:

```bash
node build.mjs
```

The script clones upstream into `upstream/`, pins the dictionaries to the cloned commit, and stops with an error if one of its patches no longer applies. If you change the userscript while upstream's version stays the same, bump `USERSCRIPT_REV` in `build.mjs` so userscript managers pick up the new build.
